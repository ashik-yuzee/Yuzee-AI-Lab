Oala AI Token Lab
Angular Implementation Guide

For: Irshad Stack: Angular 15+ · Ionic/Capacitor · Bootstrap 5 · Java Spring Boot Reference app: Oala AI Token Lab (React/Vite)
Purpose of this document The zip file you received (oala-angular-reference.zip) contains ready-to-use Angular TypeScript components, SCSS stylesheets, and detailed documentation reverse-engineered from the live Oala AI Token Lab React application. This guide tells you exactly what each file is, where it goes in your project, and what order to do things in.

1. Overview

The Oala AI Token Lab has three major UI layers that you need to replicate:

LayerWhat it isKey files in zip
Conversation UI Turn-based chat with user bubbles, Oala responses, streaming progress chat-area.*, composer.*
Protocol renderer Converts AI JSON responses into cards, timelines, tables, callouts, forms protocol-renderer.*, guidance-list.*
Mini Pathway Panel Right-side drawer that streams an AI-generated study pathway report mini-pathway-panel.*, _mini-pathway.scss

All three layers share a single design token system (CSS custom properties) defined in _tokens.scss and driven by a single accent colour (--accent: #7244c6). The accent can be changed at runtime via one JS line — the whole UI recolours automatically.

3. Project setup

Step 1 — Install required packages

Everything below should already be in your production app. Verify these are present:

npm install bootstrap@5 @ionic/angular ionicons ngx-markdown rxjs

If ngx-markdown is not installed, add it. It renders the AI's prose output. Alternatively, use marked directly and sanitise with Angular's DomSanitizer.

Step 2 — Copy the SCSS files

Copy the entire angular/styles/ folder into your project's styles directory. A suggested path:

src/
  assets/
  styles/
    _tokens.scss        ← copied from zip
    _chat.scss          ← copied from zip
    _mini-pathway.scss  ← copied from zip
    _guidance-list.scss ← copied from zip
    styles.scss         ← copied from zip (edit this)

Step 3 — Register styles in angular.json

In angular.json, under projects → your-app → architect → build → options → styles:

"styles": [
  "node_modules/bootstrap/dist/css/bootstrap.min.css",
  "src/styles/styles.scss"
]
Order matters Bootstrap must come before your styles.scss so your custom variables and overrides take effect. If you are using SCSS Bootstrap (not the CDN CSS), import it inside styles.scss before your component sheets.

Step 4 — Copy and adapt the component files

Copy each component folder from angular/components/ into your Angular project's component directory. Each component is standalone (standalone: true in the decorator), so it self-declares its imports — you do not need to add it to an NgModule.

The @import '../../styles/tokens' path at the top of each component SCSS assumes the file lives two levels deep under src/. Adjust the relative path to match your project structure.

Step 5 — Copy the services and directive

src/app/
  services/
    chat.service.ts       ← from zip
    streaming.service.ts  ← from zip
  directives/
    auto-grow.directive.ts ← from zip

Both services use providedIn: 'root', so they are available app-wide without extra registration.

Step 6 — Wire the API endpoint

The streaming service calls two endpoints. Update these to point at your Spring Boot backend:

EndpointPurposeDefault path in zip
POST /api/chatMain conversation SSE streamchange to your Spring URL
POST /api/mini-pathwayMini pathway SSE streamchange to your Spring URL

In streaming.service.ts and mini-pathway-panel.component.ts, find the fetch('/api/...') calls and replace with your absolute API URL or use Angular's HttpClient (see note in Section 9).

4. Protocol v1.3 — how JSON becomes UI

Every AI response the backend sends is a structured JSON object, not raw text. The frontend parses it and renders each section as a different UI component. This is the single most important concept to understand.

JSON shape

{
  "version": "1.3",
  "output_sections": [
    { "type": "heading",  "heading": "Your pathway options" },
    { "type": "text",     "body": "Here is a summary..." },
    { "type": "cards",    "items": [ { "title": "Certificate III", "description": "..." } ] },
    { "type": "timeline", "items": [ { "title": "Step 1: Enrol", "description": "..." } ] },
    { "type": "table",    "columns": ["Course","Duration"], "rows": [["Cert III","1 year"]] },
    { "type": "callout",  "variant": "info", "heading": "Note", "body": "..." },
    { "type": "interaction", "question": "What is your goal?", "choices": [...] }
  ],
  "meta": { "model": "gemini-2.0-flash", "duration_ms": 3200 }
}

Block type → Angular component mapping

typeRendered asCSS class
heading<h4> with border-image underline[data-output-type="heading"]
textMarkdown prose via ngx-markdown.prose-content
cardsapp-guidance-list [ordered]="false".guidance-list
timelineapp-guidance-list [ordered]="true".guidance-timeline
flowSame as timeline.guidance-timeline
tableBootstrap .table in scroll wrapper.response-table-scroll
calloutTinted box, variant controls colour[data-output-type="callout"]
scorecardAuto-fit grid of metric tiles.guidance-scorecard
progressLabelled bars (transform: scaleX).guidance-progress-list
interactionMultiple-choice fieldset or textarea.main-chat-question
pathway_mapVertical node list with connectors.guidance-pathway-map

The component that does all this switching is protocol-renderer.component. It uses *ngSwitchCase on section.type. You only need to add the <app-protocol-renderer [response]="msg.structured"> tag wherever you want to display an AI response.

Parsing the AI response

The backend should stream raw JSON (or JSON wrapped in a markdown code fence). The tryParseProtocol() function in streaming.service.ts strips the fence and parses it. If parsing fails, the component falls back to rendering the raw string as markdown. Never render raw AI text as HTML without sanitisation. Use ngx-markdown or Angular's DomSanitizer.bypassSecurityTrustHtml() only after sanitising.

5. Colour system

All colours derive from a single root variable. Changing one line recolours the entire app:

:root {
  --accent: #7244c6;  /* ← change this to any hex colour */
}

All accent tints are computed via CSS color-mix() — supported in Chrome 111+, Safari 16.2+, Firefox 113+. No polyfill needed for a modern WebView on iOS/Android.

Runtime accent change (user-settable)

// In your Settings component or accent-picker
document.documentElement.style.setProperty('--accent', '#e65c00');
localStorage.setItem('oala-accent', '#e65c00');

// On app init (e.g. in AppComponent.ngOnInit):
const saved = localStorage.getItem('oala-accent');
if (saved) document.documentElement.style.setProperty('--accent', saved);

Semantic colour tokens (from _tokens.scss)

6. AQF learning tone system

This is how course cards, timeline steps, and pathway labels get their colours. Every element that represents a qualification type receives a data-learning-tone HTML attribute. The CSS in _tokens.scss defines three CSS custom properties for each tone:

  • --course-ink — text colour
  • --course-bg — background tint
  • --course-edge — border colour

Your Angular components apply the attribute like this:

<!-- On a card, step, or tag -->
<div [attr.data-learning-tone]="item.level || item.type">
  ...
</div>

The CSS then automatically applies the right ink/bg/edge for that level. You never need to compute colours in TypeScript.

8. Chat area component

File: components/chat-area/ (html + ts + scss)

How it works

  • Subscribes to ChatService.state$ and re-renders when state changes.
  • Messages are grouped into turn groups: one user message + one assistant response, separated by a timestamp divider.
  • While streaming, a .main-chat-progress indicator is shown instead of the completed response.
  • When streaming completes, the structured field on the message is set. If it is not null, app-protocol-renderer renders it. Otherwise a markdown fallback renders the raw text.

User bubble spec

PropertyValue
Backgroundvar(--bubble-bg) — purple tint
Textvar(--bubble-text) — dark purple
Border radius18px 18px 6px 18px — right tail
Max width85% of container
AlignmentRight (justify-content: flex-end)
Font size15px

Streaming progress indicator

<div class="main-chat-progress">
  <div class="main-chat-progress-icon">   <!-- pulsing sparkle icon -->
    <ion-icon name="sparkles-outline"></ion-icon>
  </div>
  <div class="main-chat-progress-copy">
    <strong>{{ streamingStatus }}</strong>
    <p>{{ streamingText | slice:0:120 }}…</p>
  </div>
  <button (click)="stop()">Stop</button>
</div>

The icon pulses via a CSS keyframe (chat-breathe) defined in _chat.scss. No JS required.

Connecting to your Spring Boot backend

The chat area calls StreamingService.send(), which uses the browser Fetch API to POST to /api/chat and reads the response as a ReadableStream. Your Spring Boot endpoint must:

  1. Accept Content-Type: application/json POST with { conversationId, message, model, mode }
  2. Return Content-Type: text/event-stream (SSE) or application/octet-stream (raw stream)
  3. Stream lines in the format: data: {"type":"chunk","text":"..."}
  4. Send data: {"type":"done","model":"...","prompt_tokens":123,"completion_tokens":456} at the end
  5. The final assembled text should be valid Protocol v1.3 JSON

9. Composer component

File: components/composer/ (html + ts + scss)

Visual spec

  • Pill shape: border-radius: 28px
  • Border: 1px solid #e2e6ed with soft box-shadow
  • Focus: border switches to var(--accent-border)
  • Textarea: min 28px (1 line), max 176px (~7 lines), font-size 16px on mobile (prevents iOS zoom)
  • Send button: 44px on mobile (minimum touch target), 32px on desktop

Auto-grow textarea

The zip includes AutoGrowDirective. Apply it to any textarea:

<textarea appAutoGrow [maxHeightPx]="176"></textarea>

Alternatively, if using Ionic: <ion-textarea [autoGrow]="true"> — but the max-height needs to be set manually via CSS because ion-textarea's auto-grow does not cap at a maximum.

iOS safe area

The composer bottom padding uses env(safe-area-inset-bottom) so it clears the iPhone home bar. In Ionic Capacitor this is equivalent to using the Ionic CSS variable --ion-safe-area-bottom. Already handled in composer.component.scss.

Voice input

Uses the browser SpeechRecognition API — works in Chrome and Edge on desktop, and in Android Chrome WebView. Not available on iOS WebView (WKWebView blocks it). On iOS, consider using the Capacitor Speech Recognition plugin as an alternative.

@Oala mention

When the user types @o, a suggestion popup appears. Selecting it sets a flag that routes the message through a different system prompt / mode on the backend. This is purely client-side UI logic — you pass mode: 'oala' in the API request body when the mention is active.

10. Protocol renderer component

File: components/protocol-renderer/

This is the heart of the UI. Drop it anywhere you have a StructuredResponse object:

<app-protocol-renderer
  [response]="message.structured"
  (interactionSubmit)="onInteractionSubmit($event)">
</app-protocol-renderer>

The interactionSubmit event fires when a user completes a form block (multiple choice or short text). The parent handles sending the answer as a new user message.

Adding new block types

If the AI backend introduces a new type in the future, add a new *ngSwitchCase branch in the renderer template. The *ngSwitchDefault branch already handles unknown types gracefully (renders body as markdown if present).

ngx-markdown pipe

The template uses a | markdown pipe. Install and import ngx-markdown:

// app.config.ts or AppModule
import { MarkdownModule } from 'ngx-markdown';
// Add MarkdownModule.forRoot() to imports array

AQF tones on cards

Each item in the list can carry a type or level field from the AI JSON. The component binds [attr.data-learning-tone]="item.type || item.level" on each card, which triggers the AQF colour palette automatically.

12. Mini Pathway Panel

File: components/mini-pathway-panel/

What triggers it

The React reference app uses a MiniLM semantic similarity score to decide when to offer a pathway. In your Angular implementation, the backend (Spring Boot) should return a field like pathway_relevance_score in the SSE done event. If the score is ≥ 0.42, your parent component should show the offer button and open the panel.

Alternatively, you can trigger it manually: show an "Explore Pathway" button in the chat response footer and open the panel when the user clicks it.

Opening the panel

<!-- In app.component.html -->
<app-mini-pathway-panel
  *ngIf="panelOpen"
  [savedPathways]="savedPathways"
  (panelClose)="panelOpen = false"
  (pathwayGenerated)="onPathwayGenerated($event)"
  #pathwayPanel>
</app-mini-pathway-panel>

<!-- To trigger generation externally: -->
// In app.component.ts
@ViewChild('pathwayPanel') pathwayPanel!: MiniPathwayPanelComponent;

openAndGenerate(query: string) {
  this.panelOpen = true;
  setTimeout(() => this.pathwayPanel.generate(query), 50);
}

13. Sidebar component

File: components/sidebar/

Conversation list

The sidebar renders all conversations from ChatService.state$. Each conversation item shows the title (auto-generated from the first message) and last-updated time. The active conversation is highlighted with .is-active which applies var(--accent-8) background and var(--accent) text.

Session stats footer

The footer shows total token count and estimated cost across all conversations in the current session. These are derived from the promptTokens and completionTokens fields stored on each assistant message. The cost formula uses Gemini Flash pricing ($0.075/M input, $0.30/M output) — update the constants in sidebar.component.ts to match your actual model pricing.

Mobile behaviour

On viewports below 992px, the sidebar is position: fixed and slides in via transform: translateX(-100%). The parent component controls the isOpen input. A semi-transparent backdrop covers the chat area when the sidebar is open; tapping it emits the closed event which sets isOpen = false in the parent.

14. ChatService

File: services/chat.service.ts

A singleton service that holds all application state in a single BehaviorSubject. Every component subscribes to ChatService.state$ and reacts to changes. No NgRx, no component-to-component @Input chains.

Key methods

MethodWhat it does
newConversation()Creates a new conversation and makes it active
selectConversation(id)Switches the active conversation
addUserMessage(text)Appends a user message + new turn group; returns group ID
startStreaming(groupId)Sets isStreaming = true, clears streaming text
appendStreamChunk(chunk)Appends to the live streaming preview
finaliseAssistantMessage()Stores the completed message, sets isStreaming = false
setError(msg)Stores error, clears streaming state

State shape

interface ChatState {
  conversations: Conversation[];
  activeConversationId: string | null;
  isStreaming: boolean;
  streamingText: string;
  streamingStatus: string;
  error: string | null;
  model: string;
  mode: string;
}

15. StreamingService

File: services/streaming.service.ts

Handles the SSE connection to your Spring Boot backend using the browser Fetch API and ReadableStream. It does not use Angular's HttpClient because HttpClient does not support streaming responses well — raw Fetch is the correct approach here.

SSE line protocol

Each line from the server must be in this format:

data: {"type":"status","message":"Searching knowledge base…"}
data: {"type":"chunk","text":"Here is your"}
data: {"type":"chunk","text":" pathway summary…"}
data: {"type":"done","model":"gemini-2.0-flash","prompt_tokens":1200,"completion_tokens":450,"duration_ms":3100}
data: [DONE]

Spring Boot implementation tip

In Spring Boot, use SseEmitter or Spring WebFlux Flux<ServerSentEvent> to stream the response. Set the response content type to text/event-stream and write each JSON event as a data: line. Do not buffer — flush after each chunk.

Stopping a stream

The service uses AbortController. Calling StreamingService.stop() aborts the fetch. Spring Boot will detect the broken connection (socket close) and should cancel the underlying AI API call.

16. Responsive behaviour

All responsive logic is in CSS — no JS media query listeners needed. The breakpoints used:

Bootstrap classWidthBehaviour
xs (default)< 576pxFull-width bubbles, compact composer padding
sm (≥ 576px)576px+Composer padding increases, send button shrinks to 32px
md (≥ 768px)768px+Tables display normally (not stacked)
lg (≥ 992px)992px+Sidebar inline (not a drawer)
xl (≥ 1200px)1200px+Mini pathway side-by-side (not overlay)

Response table stacking

On mobile (< 576px), data tables collapse to a card-per-row layout. Each <td> uses data-label attribute with the column header text, and a CSS ::before pseudo-element renders it as a small eyebrow label. This is done entirely in CSS — no JS. The data-label values are set by the protocol renderer template. See _chat.scss and _mini-pathway.scss for the CSS.

Container queries (mini pathway panel)

The mini pathway panel uses CSS container-type: inline-size. When the panel is narrow (< 400px), internal elements switch to compact layout using @container rules. This is supported in Chrome 105+, Safari 16+, Firefox 110+. No polyfill needed in a modern WebView.

17. Ionic / Capacitor-specific notes

Icons

The component templates use <ion-icon name="...">. These are ionicons (already included with Ionic). If you are rendering outside an ion-app context, import ionicons separately:

<!-- In index.html -->
<script type="module" src="https://unpkg.com/ionicons@7/dist/ionicons/ionicons.esm.js"></script>

Safe area insets

Ionic exposes --ion-safe-area-bottom, --ion-safe-area-top, etc. The composer uses the standard CSS env(safe-area-inset-bottom) which Capacitor populates correctly. No changes needed.

Scrolling

Wrap the chat scroll area in an <ion-content> for native momentum scrolling on iOS. The auto-scroll-to-bottom logic in the component uses scrollTop = scrollHeight — in Ionic, use ionContent.scrollToBottom() instead for better iOS behaviour:

@ViewChild(IonContent) content!: IonContent;
// After each new message:
this.content.scrollToBottom(200); // 200ms animation

Keyboard avoidance

Capacitor on iOS automatically adjusts the viewport when the keyboard appears. Ensure your capacitor.config.ts has:

ios: {
  contentInset: 'always',
  scrollEnabled: false,   // let Ionic handle it
}

Speech recognition on iOS

The Web Speech API is blocked in WKWebView. Use the @capacitor/speech-recognition plugin instead. Replace the SpeechRecognition calls in composer.component.ts with the Capacitor plugin's SpeechRecognition.start() and SpeechRecognition.stop().

18. Accessibility notes

  • All icon-only buttons have aria-label. Do not remove them.
  • The streaming progress indicator has role="status" so screen readers announce updates.
  • Multiple-choice fieldsets have role="checkbox" and aria-checked on each option.
  • The mini pathway panel has role="complementary" and aria-label.
  • All interactive elements have :focus-visible outlines using var(--accent).
  • The sidebar conversation list uses aria-current="page" on the active item.
  • Tables use data-label on each <td> for screen-reader-accessible stacked layout on mobile.
  • prefers-reduced-motion media query is respected in both _chat.scss and _guidance-list.scss — animations are disabled.

19. Final implementation checklist

Work through this before calling the feature complete:

  1. Styles registered — _tokens.scss is the first import; Bootstrap precedes styles.scss in angular.json.
  2. Accent runtime-overridable — AppComponent.ngOnInit reads localStorage('oala-accent') and sets --accent on the document root.
  3. API endpoints updated — both fetch calls in streaming.service.ts and mini-pathway-panel.component.ts point to your Spring Boot server.
  4. SSE stream format matches — your Spring Boot endpoint sends data: {"type":"chunk","text":"..."} lines and a final data: {"type":"done",...} line.
  5. Protocol v1.3 JSON — the AI's assembled response is valid {"version":"1.3","output_sections":[...]} JSON. Test with a real response before wiring the UI.
  6. AQF tones in JSON — item objects from the AI include a type or level field matching one of the 14 tone values in the table in Section 6.
  7. ngx-markdown imported — MarkdownModule.forRoot() is in your app config/module so the | markdown pipe works.
  8. AutoGrowDirective declared — imported in Composer's imports: [] array (it is standalone). Verify textarea grows beyond one line.
  9. Responsive tested — check at 375px (iPhone SE), 768px (tablet), 1024px, and 1440px. The sidebar drawer, composer safe area, and mini pathway overlay should all work correctly.
  10. Table stacking tested — if the AI returns a table, resize to mobile width and confirm cells stack as labelled cards, not a horizontally scrolling table.
  11. Mini pathway panel tested — trigger generation, watch skeleton → streaming → completed report transition. Test the resize handle at desktop width.
  12. Interaction forms tested — send a prompt that returns an interaction block. Select choices and press Continue. Verify the answer is sent as a new user message.
  13. Reduced motion — in browser DevTools, enable "Prefer reduced motion" and confirm the streaming pulse and progress bar animations are suppressed.
  14. iOS keyboard — on a real iPhone, tap the composer. Confirm the keyboard does not cover the input and the send button is reachable.
  15. Error state — kill the API mid-request and confirm the error banner appears with a Retry button. Tapping Retry re-sends the last user message.
You're done when… A user can open the app, type a message, see it stream in, read a structured response with cards or a timeline, optionally open the mini pathway panel, and have their conversation remembered in the sidebar — all on both mobile and desktop.
