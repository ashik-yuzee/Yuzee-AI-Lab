Summary

  • EXP-RAG with Gemini embeddings (the default) is significantly better than Vanilla: 15 wins, 4 losses and 17 ties over 36 turns judged in both answer orders, where a win counts only if both orders agree (sign test p = 0.01). It scores higher on counselling (4.78 → 4.92) and clarity, with equal relevance, grounding and continuity within ±0.06.
  • EXP-RAG with BGE embeddings is on par with Vanilla, not significantly better: 12–8–16 (p = 0.25), total 24.58 → 24.53. It shares every speed and cost gain, so it is the right choice where no Gemini API key is available, but Gemini is the better retriever for quality.
  • Faster: median turn latency 14.2 s for both EXP-RAG variants vs 17.2 s for Vanilla (−17% pooled; −23 to −25% in the run where every mode was measured in the same window). The gain comes from before the model call (3.1 → 2.1–2.3 s), time to first token (4.0 → 3.2 s) and the review (4.4 → 2.7–2.8 s); generation time is about the same.
  • Cheaper: 36–37% lower cost per turn ($0.0027 vs $0.0042) with about a third of Vanilla's input tokens: the cached core prompt replaces the full prompt and only relevant guidance and evidence are retrieved.
  • Issues found along the way: comparison tables showed no row labels to users (fixed for every mode); the teaching review re-emitted every substantive answer in full, about 4 s per turn (fast path for EXP-RAG; Vanilla left unchanged so the baseline stays fair); and EXP-RAG wrote a short poem for an off-topic request, which breaks Oala's scope (fixed: it now declines and redirects in 4/4 runs).
  • Judge noise is large: re-scoring identical answers once moved several verdicts, so the headline uses both final runs, each judged in both orders. Single-order counts are higher (Gemini 23–8–5) but less trustworthy.

Method

  • 36 turns from 26 scenarios (single-turn and multi-turn), sent to the live server with identical model, thinking level, warehouse data, Neo4j/TimesFM intelligence and review pipeline. Only the prompt/RAG assembly differs.
  • Each EXP-RAG answer is judged against the Vanilla answer to the same turn by gemini-3.7-flash at temperature 0 with a fixed rubric (relevance, grounding, counselling, clarity, continuity). Answer order is alternated to cancel position bias; the judge is told today's date and how flattened tables are shown.
  • Answers are judged as users see them: protocol JSON rendered to visible text, internal ids excluded, comparison rows labelled.
  • Evaluation chats ran on an isolated server instance (no shared database).

Limitations

  • One generation per turn per run (two final runs pooled) and an LLM judge. Judging both orders and counting only agreed wins removes position bias but leaves many ties; a larger scenario set would be needed to show a significant BGE difference.
  • The judge (Gemini 3.7 Flash) is the same model family as the generator; it was blind to which mode produced each answer and saw answers in alternating order.
  • 18 turns across 13 scenarios cover first turns, comparisons, costs, outlook, support needs, off-topic and action requests, recognition of experience, local lookups, postgraduate choices and two multi-turn conversations; production traffic will be broader.
  • Final B reused Final A's Vanilla answers (Vanilla code was unchanged), so its latency comparison spans two time windows.
  • TimesFM forecasts were historical-only during testing (the JSA refresh was unreachable), so no turn exercised a current forecast.
